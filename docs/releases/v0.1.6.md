# 0.1.6

The third published build. Shader changes no longer need a release of this installer: the shader patch
now lives in the host repository beside the packs, and the installer checks it on every start. Nothing of
Eclipse's code travels in the patch any more, the voidstone family gained its glow and sparkle, and the
early launch can no longer undo a fetched update.

## What changed

- **The shader patch is fetched, not frozen into the jar.** `patch/patch.txt` in the host repository names
  a content-addressed bundle; the installer reads it at start-up, downloads only when its identity differs
  from what is installed, checks the SHA-256, and applies it on that launch. The window offers it the same
  way a pack release is offered. A copy still travels in the jar, so a first install works offline; an
  unreachable host keeps whatever is installed instead of reverting it.
- **The patch contains none of Eclipse's code.** A stock file we modify is stored as line edits, and
  only the inserted lines are written; a stock file needed under another name is a `COPY` the
  applier resolves from the player's own Eclipse archive. What used to be 1.3 MB of
  `block.properties` plus 28 copied per-dimension shadow shaders is now a 97 KB definition and
  60 KB of our own files: the bundle fell from 279 KB to 148 KB, the jar from 364 KB to 240 KB.
- **The early launch can no longer undo an update.** The coremod used to unpack the jar's copy whenever the
  marker differed, in place, which would have overwritten a fetched patch on the next start and merged two
  bundles in one directory. It now records where the data came from, leaves repository data alone, and
  replaces bundled data wholesale.
- **Guards against applying the wrong patch.** A manifest that names another Eclipse commit (`BASE`) or a
  newer patch format (`REQUIRES`) is refused before anything is unpacked, and the installed copy is kept.
- **Voidstone.** Energized voidstone is lit by the shader instead of a map: a slow breath around 0.08
  emission, phased by the clock alone so every block pulses together. Every voidstone variant gets sparse
  per-texel sparkle - about one texel in sixteen, briefly - with no light cast onto the floor.
- **Start-up gates and locking.** Turning the start-up check off now also stops the patch fetch; two
  launches of one instance cannot swap the data under each other.

## Content at 0.1.6

- Both resource packs are unchanged at `2026-11-19.1`; the installer will report them as up to date.
- Shader patch `6fef52f6…` (461 files, format 2, built against Eclipse `e89e6c6`), with the cable and pipe
  material work from 0.1.5 plus the voidstone behaviour.

## How to update

Replace the jar in `mods/` with this one. The next launch opens the window once: it rebuilds the shader
because the patch data changed, replaces the old patch directory (500 files to 461, with the leftover
stock files gone), checks the packs, and hands the instance back. Nothing needs deleting by hand.

The installer still does not update itself - a new installer has to be downloaded and dropped in by hand.

## Requirements and limitations

- Cleanroom 0.7.4 or newer. No OptiFine and no Nothirium.
- A shader update needs the host reachable on some launch. While it is not, the installed patch is kept
  and nothing is rebuilt.
- The window still has no progress for the Eclipse download beyond the log; the band reports what was
  fetched once it finishes.
- No CurseForge listing: the installer downloads at install time, which their rules do not allow.
