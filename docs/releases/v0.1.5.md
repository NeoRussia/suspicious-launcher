# 0.1.5

The second published build of the Suspicious Speculars installer. The window behaves the way it was
meant to from the start: it opens once after an install or an update and stays out of the way
afterwards, and a pack release that is already out is offered as an **update** rather than a reinstall.

## What changed

- The window opens on the first launch after an install or an update, and only then. The in-game
  popup is gone; `/suspiciousspeculars update` is the one way to bring the window back while playing.
- A pack release newer than the installed one is announced: the coremod reads `packs.txt` from the
  pack host, compares the versions as numbers, and the window labels it `update <version> available`
  with an **Update** button. Before, the only offer was a reinstall of what was already there.
- The completeness check covers the shader pack, Demonica and both resource packs, so a half-installed
  instance counts as work to do rather than as done. Any verdict now clears the one-relaunch guard,
  and an explicit request to install on the next start outranks it - a failed relaunch no longer
  leaves the installer refusing to try again.
- `/suspiciousspeculars help` lists the subcommands, and they complete on Tab the way a Forge
  command does.
- Hardening around the downloads: bounded timeouts, a written `status=error` with the reason instead
  of a silent stop, an idempotent finish, and every failure also reaching the client log. OptiFine and
  Nothirium are named as red lines, and a second shader pack in `shaderpacks/` is reported as a
  conflict instead of being ignored.
- The build names itself from the jar's own `mcmod.info`, so the logs and the state file carry the
  exact jar rather than a constant that lagged behind it.
- An existing shader is repatched when the installer's *patch data* changes, not only when the file is
  missing or the base is different. Before, the check was "does the file still match the hash this
  installer recorded", which is no evidence that it was built from this release's patch: a 0.1.4
  install would have kept its old shader and never received this release's cable and wire materials.
  The state now records the patch data it patched with, a mismatch counts as work, and the window
  opens on that launch to rebuild the shader - one relaunch, like any other install.

## Content at 0.1.5

Both resource packs are at `2026-11-19.1`:

- Specular maps for connector-textured blocks are generated at the texture's own size instead of a
  16x16 resample. Under CTM the shader indexes a map by the tile's uv sub-rect, so the old maps put
  gloss and emission a quarter out of register - the glow landed as small squares at tile corners on
  coil walls, fusion glass, hazard signs, pipes and multiblocks. 90 maps across the two packs.
- Treated wood planks and door faces move from F0 226 to 240, above the metal cut-off, so the sheen
  takes the wood's colour instead of reading as a white dielectric highlight.
- GregTech pipes, cables and bare wires get their material from block ids rather than maps, because
  their geometry never reaches the sprite pass. The installer's shader edit carries the ids
  (`block.properties` 701-706) and the branch in `all_solid.fsh` that uses them; wood pipes are kept
  matte by a luma test on the sprite.

## How to update

Replace the jar in `mods/` with this one. The next launch opens the window once; it installs the
current packs if the instance is on an older version, rebuilds the shader if it was patched by an
older installer, and then hands the instance back to the launcher - so nothing has to be deleted by
hand. The installer does not update itself - a new installer has to be downloaded and dropped in by
hand.

## Requirements and limitations

- Cleanroom 0.7.4 or newer. No OptiFine and no Nothirium.
- The window still has no progress for the Eclipse download beyond the log; the band reports what was
  fetched once it finishes.
- A pack update is offered, not applied behind your back: the window in game says so, and
  *Quit and install* sets it up for the next launch.
- With the check at start-up turned off (`/suspiciousspeculars toggle`), nothing is checked, repaired or
  rebuilt at launch; `/suspiciousspeculars install` is the way back.
- No CurseForge listing: the installer downloads at install time, which their rules do not allow.
